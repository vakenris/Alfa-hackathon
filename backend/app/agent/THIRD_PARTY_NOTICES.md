# Зависимости, модели и локальные материалы

AI-компонент использует существующие зависимости проекта: Python standard library,
Pydantic (DTO/валидация) и общий HTTP-клиент на httpx. Новых production-библиотек,
агентных фреймворков и отдельного RAG не добавлено. Точные установленные версии и
лицензии для итоговой поставки должны фиксироваться общим dependency lock/образом
проекта; этот файл не заменяет их licence notices.

Разрешённые в официальной презентации модели: Gemma 4 26B A4B, GLM-5.3-Flash,
Qwen3.6 35B A3B, DeepSeek-V4.1-Flash, Qwen3-VL-30B-A3B-Instruct, kimi-k2.6.
Это названия из кейса, не API identifiers. Конкретный model ID и endpoint задаёт
подтверждённая конфигурация организаторов. В сохранённом старом live-тесте был
`deepseek/deepseek-v4.1-flash`; текущая реализация с ним заново не запускалась.
Веса моделей не поставляются и не загружаются; условия API/моделей уточняет команда.

Локальные CSV хакатона, банковские PDF, сверенные выдержки, OCR, выбранные профили
и результаты тестов находятся только в Gitignored `local_test_data/`. Их нельзя
добавлять в коммиты или передавать сервисам без отдельного разрешения.
`backend/app/agent/demo.py` содержит явно синтетические данные и заданный ответ
для демонстрации интерфейса. Это не банковский документ и не реальная генерация.

Для чтения предоставленной официальной презентации применялись локальные Windows
PDF/OCR API. Это средство подготовки тестовых материалов; production-агент не
зависит от Windows OCR, не вызывает внешние OCR-сервисы и не скачивает модели.

Сборку Docker, фиксацию версий и финальную упаковку общей системы выполняют
владельцы соответствующих компонентов. Этот рефакторинг не меняет их файлы.
