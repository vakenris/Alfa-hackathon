# Локальная проверка AI-агента на новостях и данных организаторов

Это **добавочный тестовый стенд**, не замена `backend/app/agent/` и не второй бэкенд. Файлы архива нужно поместить **только** в `backend/app/agent/`, не переписывая существующие модули. Стенд использует `CompanyResponse`, `NewsArticleResponse`, `AnalyticsDocument` из существующего проекта. Запуск из **корня репозитория**.

## Что уже в наборе

- `evaluation/real_news_cases.json`: 4 проверенных внешних события с датой, источником, ссылкой и вопросом для ручной оценки. Поле `content` — *наш краткий пересказ* первоисточника, а не копия статьи и не дословная цитата. Убедись, что выбранный news URL действительно соответствует ожидаемому содержанию.
- `evaluation/demo_company.json`, `demo_counterparties.json`: **полностью синтетические** данные для проверки форматирования, не компании хакатона.
- `evaluation/demo_bank_documents.json`: пустой список, чтобы не имитировать позицию Альфа-Банка.
- `local_test_harness.py`: проверка данных и опциональный live-запуск именно предоставленного `AgentInsightEngine`.

## Без сети и без списания средств

```powershell
python -m backend.app.agent.local_test_harness list
python -m backend.app.agent.local_test_harness inspect
python -m backend.app.agent.local_test_harness validate --case rate_hold_2026_10_23 --company backend/app/agent/evaluation/demo_company.json --counterparties backend/app/agent/evaluation/demo_counterparties.json --bank-documents backend/app/agent/evaluation/demo_bank_documents.json
```

`validate` подтверждает только совместимость JSON с DTO и корректность временного порядка банковских публикаций. **Это не проверка качества агента, RAG или LLM.** Режим `inspect` показывает требуемые поля DTO в твоей текущей ветке.

## Как подставить данные организаторов

1. Выбери одну реальную компанию из датасета, лучше с известной отраслью и заметными признаками. **Не подменяй выручку**: `revenue_company=1000` — заглушка, она должна оставаться заглушкой, не 1000 рублей реальной выручки.
2. Преобразуй **одну строку** в объект JSON, соответствующий `CompanyResponse`. Не пытайся угадать схему: используй команду `inspect` и существующий mapper бэкендера. Сохрани, например, `backend/app/agent/evaluation/company_local.json`.
3. Если есть данные платёжных связей, сделай массив `CounterpartyItem` и сохрани `.../counterparties_local.json`. Обрати внимание: `SUPPLIER` и `CUSTOMER` в upstream-поле — технические направления потоков, **не подтверждение хозяйственных отношений**. Не превращай суммы платежей в выручку.
4. Для банковских материалов нужен массив объектов `AnalyticsDocument`, например:

```json
[
  {
    "article": {
      "id": 33001,
      "title": "РЕАЛЬНОЕ название аналитического материала",
      "source": "Альфа-Банк",
      "published_at": "2026-01-01T12:00:00+03:00",
      "category": "Аналитика",
      "content": "ТОЧНЫЙ фрагмент из предоставленного PDF",
      "is_bank_analytics": true
    },
    "source_url": null,
    "provenance_status": "unverified",
    "source_document_id": null,
    "source_page": null,
    "source_hash": null
  }
]
```

Значения в примере — **шаблон, не готовый банковский источник**. Не копируй вымышленные дату/текст в реальные тесты. Заполни из конкретного организаторского PDF. `verified` и настоящий `source_document_id` допустимы только при прослеживаемом происхождении документа, вручную или через доверенный реестр. Иначе агент обоснованно откажется утверждать, что банк действительно высказал эту позицию.

Сохрани файл как `.../bank_local.json`. Если дата банковского документа позже даты новости, стенд отклоняет сценарий: поздняя публикация не может служить свидетельством для анализа на более раннюю дату.

## Тест с настоящей моделью — отдельное осознанное разрешение

**Не запускай, пока не согласован расход командного API-бюджета**, не подтверждены gateway URL, alias модели и данные авторизации. Пример для PowerShell; не размещай ключи в коде, git, снимках экрана или сообщениях:

```powershell
$env:AGENT_LLM_API_URL = "https://changellenge.up.railway.app/v1/chat/completions"
$env:AGENT_LLM_MODEL = "deepseek/deepseek-v4.1-flash"
$env:AGENT_LLM_AUTH_HEADER = "Authorization"
$env:AGENT_LLM_AUTH_VALUE = "Bearer <ВСТАВЬ_КЛЮЧ_ЛОКАЛЬНО>"
$env:AGENT_LLM_MAX_OUTPUT_TOKENS = "4096"
python -m backend.app.agent.local_test_harness run --case rate_hold_2026_10_23 --company backend/app/agent/evaluation/company_local.json --counterparties backend/app/agent/evaluation/counterparties_local.json --bank-documents backend/app/agent/evaluation/bank_local.json --live --allow-live --out backend/app/agent/evaluation/result_local.json
```

**Не вставляй ключ в чат.** Команда `run` использует live-сеть **только при одновременном наличии `--live --allow-live`**. У агента лимит до четырёх вызовов LLM за один анализ, включая возможную recovery-ветку. Суммарный бюджет в рублях скрипт не контролирует; требуется согласование с владельцем бюджета/лимитов команды. `result_local.json` может содержать бизнес-данные и должен оставаться локальным, не попадать в git.

Для отдельной проверки лексического `BackendAnalyticsSource` используется `--retrieval lexical` по умолчанию. `--retrieval mock` отдаёт документы без релевантного поиска и служит только для проверки потока данных.

## Как оценивать ответы

Смотри не только на `verification.passed`. Для каждой новости вручную проверяй: (1) верное событие и дата, (2) связь с конкретной компанией и её реально известными признаками, (3) корректный механизм, (4) нет выдуманных ставок по договору, выручки, обязательств и контрагентов, (5) реальная и корректно атрибутированная банковская позиция или честное её отсутствие, (6) предлагаемые действия выполнимы и содержательны, (7) для нерелевантной новости агент не выдумывает бизнес-последствия.

**Отдельная известная проблема:** `reference_url` новости доступен в каталоге стенда для ручной сверки, но старый `NewsArticleResponse` может не передавать URL в `EvidenceItem`. Не объявляй полное цитирование новостей реализованным, пока команда не договорится о сохранении `source_url` в общем DTO.

Этот стенд **не** проверяет реальную БД, PDF ingestion, весь RAG-корпус, API worker, SSE, фронтенд или процесс авторизации. Их интеграция — задача команды.

## Проверка этого набора

Синтаксис `local_test_harness.py`, каталог JSON и команда `validate` были проверены в изолированной копии кода **с упрощёнными имитациями общих DTO**. Это подтверждает работу командной оболочки, но не окончательную совместимость с настоящими схемами вашего репозитория: её нужно проверить в вашей ветке. Live-запрос к LLM не выполнялся.
